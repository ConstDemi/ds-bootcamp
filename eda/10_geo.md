# 10 — География поиска: ярусы, карты регионов, мягкий бонус

Код:
- `src/geo.py`: карты и правила. Центроиды локаций, поиск города в тексте (`CityFinder`, перенос `find_city2` из `eda/geo_eda.py`), карты по train (`GeoMaps`: регион → доли городов, пары «город поиска → город объявления», соседи по центроидам), правила «запрос → ярусы», `tiered_top` (top-k по ярусам с добором из всего корпуса) и `rrf` (с необязательным бонусом).
- `src/geo_run.py exp --sparse {stem,lemma}` считает все правила на валидации (~2.5 / 4 мин, GPU, пик RAM ~6 ГБ) и пишет `work/geo/val_{stem,lemma}.parquet`. `geo_run.py final ...` прогоняет выбранную конфигурацию на валидации и бенчмарке.
- `experiments/geo_report.py` строит таблицу, бутстреп и выбор на половинах. `experiments/geo_final_report.py` даёт срезы, кривую и промахи.

Новых пакетов нет, `BallTree` берётся из scikit-learn, он уже в requirements.

## Как устроено

1. Для каждого запроса один раз считаются полные векторы скоров по всему корпусу (189k): BM25 через `index.scores`, bge-m3 как матрица «запросы × корпус» на GPU батчами по 128.
2. Правило выдаёт ярусы, то есть непересекающиеся списки позиций корпуса по приоритету. Каждый источник берёт top-300 по ярусам: сначала лучшие из яруса 1, потом из яруса 2 и так далее, в конце добор из всего корпуса. BM25 берёт только скор > 0, как в `sparse.py`.
3. Два списка сливаются через RRF k=60 без явных ярусов, как в `hybrid.py`. В мягких правилах к RRF-скору прибавляется бонус объявлениям «своих» локаций.
4. Проверка: правило C0R0 («как сейчас») воспроизводит гибрид из `08_hybrid.md` до 4-го знака (**0.8023**).

**Против утечки.** Карта регионов, пары и фильтр «негеографичных» названий городов (ростов → ростовая кукла и т.п.) строятся по `train[train_mask]` для валидации и по полному train для бенчмарка. Центроиды и словарь названий берутся из атрибутов объявлений (координаты, адрес «Место оказания услуг»), это не ответы.

## Правила

Регионы: search_location_id, которого нет ни у одного объявления, 529 запросов валидации. Из них 98 приходятся на 621540 («вся Россия»).

| правило | ярусы (потом всегда весь корпус) |
|---|---|
| C0R0 | как сейчас: регион → весь корпус |
| R1 | все города, которые выбирали из этого региона в train |
| R2_x | только города с долей выборов ≥ x (0.3%, 1%, 2%, 5%) |
| R2t_0.01 | ярус 1: города ≥ 1%, ярус 2: остальные города R1 |
| R3 / R32_0.01 | ярус 1: город из текста запроса, ярус 2: R1 / города ≥ 1% |
| R4a / R4b | главный город, потом остальные / ярусы по доле ≥10%, 1–10%, <1% |
| R3_4b | город из текста, потом R4b |
| R5 | только город из текста, иначе весь корпус (вариант «вся Россия») |
| **RSOFT_w** | списки из плоского пула R1, к RRF-скору +w объявлениям городов с долей ≥ 1% |

Города (2471 запрос):

| правило | ярусы |
|---|---|
| C1_30 / C1_100 | свой город → соседи ≤ 30 / 100 км по центроидам |
| C2 / C2s | свой город → все пары из train / пары с долей ≥ 1% строк этого города поиска |
| C3 / C3s | свой город → соседи ≤ 100 км ∪ пары (все / ≥ 1%) |
| C4 / C4all | один плоский пул «свой + соседи ≤ 100 км + пары ≥ 1% (все пары)», без приоритета своего города |
| **SOFT_w** | списки из плоского пула C4, к RRF-скору +w объявлениям своего города |

Для масштаба бонуса: максимум RRF одного источника равен 1/61 ≈ 0.016, у объявления, найденного обоими, до 0.033.

**Потери пула.** Здесь это доля правильных ответов вне ярусов, то есть до добора из корпуса. По всем запросам 1.8%: у городов 2.0% (пул «свой + ≤100 км + пары ≥1%», медиана 4.4k объявлений), у регионов 1.0% (пул R1, медиана 66k), у 621540 1.0%. Мягкие правила не отсекают пул, бонус только переставляет объявления внутри него. Поэтому потолок @300 вырос с 0.909 до 0.942.

Бенчмарк: карты построены по полному train, у 4.5% запросов в тексте найден город. Топ-50 совпадает с `answer_02_hybrid.csv` на 79%.

## Что сработало и почему

1. **Регионы — главный рычаг.** С поиском по всему корпусу регион соревнуется со всей страной и получает 0.49. Если сузить поиск до городов, куда из этого региона реально ходят (доля ≥ 1%), выходит 0.78. Порог важен: R1 со всеми городами даёт только 0.66, потому что у Москвы+МО в R1 сотни мелких локаций и пул в 108k. Порог 5% уже режет правильные ответы: в ярусах их 77%.
2. **Мягкий бонус лучше жёсткого сужения и ярусов.** RSOFT_0.02 берёт списки из всего региона, а города ≥ 1% получают бонус. Выходит лучше жёсткого R2_0.01 (0.785 против 0.776), и 11% ответов из мелких городов не теряются. При бонусе ≥ 0.03 он становится строгим (всё с бонусом выше всего без бонуса), поэтому 0.03 и 0.05 совпадают и хуже 0.02.
3. **Ярусы для городов почти бесполезны.** В городе обычно ≥ 300 объявлений, и dense целиком заполняет свой top-300 из яруса 1, до соседей очередь не доходит. Ярус 2 достаётся только BM25, когда в городе мало совпадений. Отсюда C1–C3 дают +0.002…+0.005.
4. **Плоский пул без приоритета своего города вредит.** C4 даёт −0.013, C4all (пары без порога, пул 74k) −0.215. Свой город остаётся сильнейшим сигналом (93% выборов). SOFT_0.015 объединяет оба подхода: соседи ≤ 100 км и частые пары участвуют в RRF, а свой город получает бонус примерно в «один источник на ранге 1». Это +0.013 на городах.
5. **Город в тексте почти ничего не даёт.** R3, R32 и R5 в пределах шума: в валидации только 30 региональных запросов с названием города, в бенчмарке около 4.5% всех запросов. Для 621540 правило R5 («город из текста, иначе вся страна») ничего не меняет. Названный город в основном и так попадает в пул через текстовое совпадение.
6. **«Вся Россия» (621540).** Карта 621540 — это ~590 локаций, по сути популярные города. RSOFT_0.005 (маленький бонус Москве, СПб и другим городам ≥ 1%) даёт +0.066 [+0.015; +0.122] на 98 запросах. Выбор держится на обеих половинах, но интервал широкий. Сильный бонус (R4a, жёсткий R2_0.01) здесь вредит, потому что пользователи «всей России» выбирают по всей стране.

| 1–10% | 55 / 12 | 0.818 / 0.750 |
| < 1% | 31 / 25 | 0.355 / 0.640 |
| нет в карте | 5 / 1 | 0.20 / 0 |

Большая часть оставшихся промахов (72 из 119) приходится на главный город региона, где география уже правильная. Там дело в тексте и в выборе среди равнозначных объявлений. Около 30 промахов — ответы из мелких городов (< 1%) и локаций вне карты, это остаточная гео-потеря.

Что осталось для регионов: реранкер над топ-300 (ответ там у 43% промахов). Признаки: доля города в регионе, расстояние до главного города, совпадение фильтра вида услуги. Бонус по доле можно сделать не ступенькой (≥ 1%), а плавным, например w·log(share). Отдельно стоит учитывать вид услуги из фильтра, запросы вроде «заберу диван [Вывоз мусора]» проигрывают именно из-за него.
