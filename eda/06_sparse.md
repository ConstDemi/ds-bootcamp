# 06 — Sparse-ретривер (BM25 + стемминг)

Код: `src/sparse.py` (индекс и поиск), `experiments/run_sparse.py` (замеры и выгрузка кандидатов). Запуск из корня репозитория: `python experiments/run_sparse.py` (~3.5 мин на CPU, пик памяти 5.1 ГБ, считает все три варианта). Пакеты: `bm25s==0.3.11`, `PyStemmer==3.1.0`.

## Что сделано

- Токенизация: нижний регистр, ё→е, токены `\w+`, стемминг Snowball russian (PyStemmer). Латиница не стеммится. Стоп-слов нет, частые слова гасит IDF.
- BM25 (bm25s, вариант lucene, k1=1.5, b=0.75). Скоры считаются по всему корпусу, повтор слова в запросе считается один раз. Результат сверен с `bm25s.get_scores`.
- Режимы:
  - **all**: поиск по всему корпусу;
  - **geo**: если `search_location_id` есть среди `item_location_id`, это город, и ищем среди объявлений города. Регион и «вся Россия» ищутся по всему корпусу. Если в городе меньше k объявлений с ненулевым скором, добираем до k лучшими из всего корпуса без повторов.
- Варианты текста документа:
  - a — `item_text` (заголовок + очищенные параметры + 500 символов описания);
  - b — заголовок ×2 + `item_text`;
  - c — заголовок + параметры, без описания.
- Char n-gram TF-IDF не делал. На полном тексте матрица 189k × (3–5)-грамм не укладывается в ~6 ГБ, а на опечатки нашлось всего 2 примера из 14 (ниже).

## Recall@50 на валидации (3000 запросов)

| вариант | all | geo | построение индекса, с |
|---|---|---|---|
| a: item_text | 0.4009 | 0.7381 | 47 |
| **b: заголовок ×2** | **0.4139** | **0.7445** | 38 |
| c: без описания | 0.3295 | 0.6507 | 19 |

- Поиск занимает ~1 мс на запрос в обоих режимах, один поток. Это время `get_scores` плюс argpartition, без построения индекса.
- b лучше a на 0.006. Это меньше порога «заметно» 0.01, но b не хуже и дешевле.
- Описание нужно: без него (c) recall падает на 0.09.
- Гео даёт +0.33: 0.41 → 0.74.

Для сравнения бейзлайн «популярное в городе» даёт 0.146.

## Кандидаты (вариант b, топ-300)

Файлы `work/cands/sparse_{val,bench}_{all,geo}.parquet`, колонки: `query_id`, `item_id` (str), `score` (float32, сырой BM25), `rank` (int32, с 1).

- Валидация: 875 244 строки, бенчмарк: 713 781.
- В geo `score` может расти при переходе от городских кандидатов к добору: у добора свой глобальный скор. Порядок задаёт `rank`.
- У 122 запросов валидации и 103 бенчмарка меньше 300 кандидатов: мало документов, где есть хоть одно слово запроса.
- 1 запрос бенчмарка остался без кандидатов: «сабутыльник», ни одного стема нет в словаре. Гибриду нужен запасной источник кандидатов.
- Скоры по запросу на вспомогательной валидации лежат в `work/sparse_val_{all,geo}_perq.parquet`.

## Промахи (geo, вариант b)

- Промахов (recall@50 = 0) 757 из 3000. У 341 из них правильный ответ всё же есть в топ-300.
- Грубые причины по всем 757 промахам:
  - у запроса нет общих стемов со всем документом ответа: 20%;
  - нет общих стемов с заголовком ответа: 44%;
  - ответ в другом городе при городском запросе: 17%.

## Выводы

1. BM25 с Snowball-стеммингом и гео-пулом даёт **0.745** Recall@50. Это в 5 раз больше популярности (0.146), и результат держится на срезах «новый текст» (0.737) и «ответ без истории» (0.755). Такой ретривер годится как основной генератор кандидатов. Внутри топ-300 geo recall 0.86, этого хватает для реранкера.
2. Лучший текст документа — заголовок ×2 + `item_text`, описание нужно. Разница между a и b в пределах шума.
3. Главная дыра — регионы и «вся Россия»: 0.487, 18% запросов. В примерах ответ почти всегда лежит в конкретном городе региона. Сужение «регион → его города» (по парам search_location → item_location из train) должно дать больше всего.
4. Второй источник промахов — лексический разрыв: синонимы, общее↔частное, намерение без общих слов. У 44% промахов нет общих стемов с заголовком. Эту часть должен закрывать dense-ретривер.
5. Фильтры (`search_infm_params_text`) sparse-поиск не использует. Запросы вида «голубое» + фильтр «Маникюр» можно спасти бустом по совпадению вида/типа услуги (EDA: фильтр почти безопасен).
6. Опечатки заметны, но редки (2 из 14 разобранных). Char n-gram TF-IDF не приоритетен.
