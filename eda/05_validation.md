# 05 — Валидация

Код: `src/validation.py` (построение, метрика, срезы), `experiments/check_validation.py` (все проверки ниже).
Запуск из корня репозитория: `python src/validation.py` (~4 с, ~0.6 ГБ), затем `python experiments/check_validation.py` (~20 с, ~1 ГБ).

## Схема по шагам

1. Строки train склеиваются в запросы: `query_key` = нормализованный текст | search_location_id | фильтры (нормализация: нижний регистр, ё→е, одиночные пробелы).
2. Кандидаты — запросы, у которых хотя бы одно выбранное объявление есть в корпусе `benchmark_items` (26 549 запросов, 12 174 текста). Правильные ответы — только эти объявления: на бенчмарке всё тоже ищется в корпусе.
3. На каждый текст берётся один случайный запрос-кандидат: в бенчмарке тексты не повторяются.
4. Тексты отбираются по 4 слоям: (текст встречается в других запросах train) × (есть непустой фильтр). Доли слоёв берутся из бенчмарка. Без слоёв условие «ответ в корпусе» тянет к частым текстам и к запросам с фильтром.
5. Все строки отложенных запросов (3 776 строк) исключаются из обучения: `train_mask = False`. Другие запросы того же текста остаются в train, как в бенчмарке.
6. Флаги запроса считаются один раз и хранятся в таблице:
   - `text_in_train`: текст есть в **train[train_mask]**; у бенчмарка этот флаг считается по **полному** train;
   - `has_filter`;
   - `is_region`: локации нет ни у одного объявления, то есть это регион или вся Россия;
   - `target_has_history`: хотя бы один правильный ответ выбирали в строках train[train_mask].

   `describe_queries` и `slices` только читают эти колонки, поэтому train для валидации и train для бенчмарка перепутать нельзя.

Размер валидации — 3000 запросов, seed 42.

- Строк отложенных запросов в train[train_mask]: **0**. Отложено 3 776 строк, и столько же строк у отложенных запросов в полном train.
- Повторов текста в валидации нет.

Разброс по seed: std 0.0034, от 0.146 до 0.154. Погрешность среднего одной валидации — std/√n ≈ 0.0065, то есть 95%-интервал ±0.013 при recall ~0.15.

Наборы разных seed совпадают на ~43%: в слое «новый текст без фильтра» берётся 1 402 из 1 894 доступных текстов. Поэтому разброс по seed занижает настоящую неопределённость, и ориентироваться лучше на std/√n. Две модели на одной и той же валидации сравниваются точнее: их ошибки на общих запросах коррелированы, так что разницу в 0.01 и больше можно считать заметной. Для уверенности стоит проверить её парным бутстрепом по запросам.

## Что осталось непохожим на бенчмарк

1. **История ответа.** У 53% отложенных запросов ответ уже выбирали в train, потому что ответы валидации по построению взяты из выборов train. На бенчмарке такая доля, скорее всего, заметно ниже: из корпуса в train встречается только 9.6% объявлений. Из-за этого всё, что опирается на популярность, id объявления или историю «текст → объявление», на валидации переоценено. Такие методы надо смотреть на срезе **«ответ без истории»**. Контентный поиск завышается меньше, но и его стоит смотреть на обоих срезах.
   Как оценить долю p на бенчмарке: после сабмита «популярного в городе» p ≈ recall_платформы / 0.274. Дальше можно пересчитывать валидацию так: p·R(история) + (1−p)·R(без истории).
2. **search_category = 0** (9% бенчмарка) не воспроизводится: в train таких запросов 34 строки. Это сложные запросы вне услуг, и на них платформа, вероятно, даст меньше, чем валидация.
3. **Полное совпадение запроса с train**: у бенчмарка 4.45%, у валидации 0 по построению. Эффект небольшой и в пользу бенчмарка.
4. Тексты валидации немного короче: 3.08 слова против 3.20. Доля текстов из 5 и более слов — 11.4% против 14.2%.

## Как пользоваться

```python
import sys; sys.path.insert(0, "src")
from validation import load_validation, recall_at_k, slices
val_q, val_labels, train_mask = load_validation()   # файлы из work/
train = pd.read_parquet("data/train.parquet", columns=[...])  # нужные колонки, порядок строк исходный
train_fit = train[train_mask]
preds = my_model(val_q, train_fit)                   # dict query_id -> список item_id
r = recall_at_k(preds, val_labels)                   # Recall@50 по запросам; r.mean() — метрика
print(r.mean(), slices(r, val_q), sep="\n")
```

Файлы в `work/`:
- `val_queries.parquet` — в формате `benchmark_queries` (query_id, search_*), плюс `text_norm`, `query_key`, `text_in_train`, `has_filter`, `is_region`, `target_has_history`;
- `val_labels.parquet` — query_id, item_ids (список правильных ответов);
- `train_mask.npy` — bool длины train (497 673), True = строку можно использовать для обучения.

Учиться можно только на train[train_mask]. Индексы, словари популярности и дообучение моделей тоже строятся только по нему. Для бенчмарка всё пересчитывается на полном train.

Чтобы получить другой seed или размер, используйте `build_validation(n_queries, seed, train=load_train())`. Для флагов бенчмарка вызовите `add_flags(bench, set(train.text_norm), region_location_ids())`: здесь берётся полный train.
