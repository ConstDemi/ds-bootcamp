# 04. Текстовый матчинг и фильтры

Скрипт: `eda/text_eda.py`. Время работы около 35 с, пик RAM около 6 ГБ. Токенизация: `lower`, `ё→е`, `\w+`. Из запроса выброшены предлоги и союзы, а также токены длиной 1. «Стемминг» здесь грубый: сравниваются префиксы длины 5.

Для текстовой части взяты две выборки:
- **R**: 50 000 случайных строк train. Здесь популярные запросы весят больше, по числу кликов.
- **Q**: одна случайная пара на уникальный запрос, всего 50 000 запросов. Это ближе к benchmark, потому что метрика макро-усредняется по запросам. В Q2 показано, что benchmark по статистикам совпадает с уникальными запросами train, а не со строками.

---

## 1. Лексическое пересечение «запрос ↔ выбранный item»

Доля пар, где хотя бы один токен запроса есть в поле:

| поле | R exact | R prefix5 | **Q exact** | **Q prefix5** |
|---|---|---|---|---|
| title | 71.3% | 83.4% | 62.7% | 77.6% |
| params (`item_infm_params_text`) | 57.3% | 70.6% | 50.7% | 64.2% |
| description | 77.2% | 90.0% | 78.4% | 90.5% |
| title + params | 82.8% | 91.6% | 75.5% | 87.3% |
| любое поле | 92.4% | 97.3% | 89.7% | 96.0% |

Сколько токенов запроса покрыто (prefix5):

| метрика | R | Q |
|---|---|---|
| **все** токены запроса есть в title + params (exact) | 50.6% | 18.0% |
| **все** токены в title + params (prefix5) | 62.0% | 28.7% |
| все токены только в title (prefix5) | 48.3% | 16.6% |
| все токены в title + params + desc (prefix5) | 83.4% | 61.7% |
| средняя доля покрытых токенов: t+p / t+p+d | 0.78 / 0.91 | 0.59 / 0.81 |
| совпадение только в description (в t+p ничего нет) | 5.7% | 8.7% |
| нулевое пересечение по всем полям (prefix5) | 2.7% | 4.0% |

- **Морфология** даёт +12–15 п.п. на title и +10 п.п. на полном покрытии в title+params. Нормализация обязательна.
- **Description** важен. В 8.7% запросов (Q) совпадение есть только в нём. Полное покрытие запроса растёт с 29% (t+p) до 62% (t+p+d).
- **Длинный хвост запросов** (Q) гораздо «беднее» лексически, чем популярные (R). Запросы с 3+ токенами почти никогда не покрываются целиком. Значит, нужен OR/BM25-скоринг, а не AND-матчинг.
- Оговорка: в params есть служебные слова ключей («Вид услуги», «Место оказания услуг», «Тип стоимости»…). Токен запроса «услуги» совпадает с ними тривиально, поэтому покрытие params немного завышено.

**Нулевое пересечение: 15 примеров** (запрос → title; из выборок R и Q)

| запрос | title выбранного item | причина |
|---|---|---|
| сапожник | Ремонт обуви сумок и изделий из кожи | синоним (профессия ↔ услуга) |
| ногти | Маникюр гель-лак педикюр | синоним (объект ↔ услуга) |
| подстричь газон | Покос травы триммером | синоним / перефраз |
| пробивка туалета | Устранение засоров и прочистка канализации | синоним / перефраз |
| корчевание пней | Уборка дачных участков, спил деревьев | смежная / более широкая услуга |
| сварщик | Сварочные работы, аргон… | словообразование (общий префикс «свар» из 4 символов, prefix5 не ловит) |
| косы | Плетение афрокосичек, афрокудри | композит + морфология |
| фотоателье | Фото на документы | композит |
| ямобур | Услуги мотобура | вариант термина / композит |
| мастер на эбаксдную смалу заливка на пол | Эпоксидные наливные полы | опечатки + морфология |
| мукалатура | Прием макулатуры… | опечатка |
| бобкет | Услуги бобкэта | опечатка / транслитерация |
| chalet house with a swimming pool, vat, and sauna | Дом шале, Бассейн, чан, баня | другой язык |
| груминг | Покос травы | шум (нерелевантный клик) |
| гадание на картах | «345» | неинформативный title (смысл в description) |

Грубое распределение по причинам: синонимы и перефразы около 40%, морфология, словообразование и композиты около 25%, опечатки и транслит около 20%, шум и пустые title около 15%.

**Что это значит для решения.** Индексировать title, params и description раздельно с разными весами. Нужны лемматизация или стемминг и char n-grams: они ловят «сварщик/сварочные», «косы/афрокосички» и опечатки. Для оставшихся около 4% пар с нулевым пересечением, а также для синонимии в неполных совпадениях, нужен dense или семантический канал. Ещё одна опора — «память» по train: запрос → кликнутые item.

## 2. Статистика текста запросов

| | train, строки (R) | **train, уникальные** | **benchmark** |
|---|---|---|---|
| n | 50 000 | 74 529 | 2 452 |
| токенов: среднее / медиана | 2.34 / 2 | 3.10 / 3 | 3.20 / 3 |
| 1 токен | 19.5% | 4.4% | 4.4% |
| 2 токена | 45.1% | 30.5% | 28.6% |
| 3 токена | 22.3% | 33.2% | 31.9% |
| 4+ токенов | 13.1% | 31.9% | 35.2% |
| есть латиница | 2.8% | 7.6% | 4.9% |
| есть цифры | 1.6% | 4.6% | 3.8% |
| токен не встречается в title корпуса benchmark | 4.0% | 15.3% | 15.4% |
| токен не встречается ни в одном title (корпус + train) | 2.0% | 9.1% | 10.7% |
| токен OOV по словарю title + params | 1.4% | 6.4% | 7.5% |
| токен OOV по prefix5 (title + params) | 0.5% | 2.3% | 2.6% |
| **«похоже на опечатку»**: OOV в title и встречается ≤2 раз среди запросов train | 1.2% | 6.9% | **9.5%** |

- Benchmark статистически совпадает с **уникальными** запросами train, а не со строками. Он длиннее и хвостовее. Опечаток в нём немного больше: 9.5% против 6.9%. Эта оценка сверху, она включает топонимы и редкие словоформы («бородавку», «цимлянск»). Примеры явных опечаток: «бровейцвнты», «компьюторов», «наращеввние», «минитоактором», «унитазетранению».
- **37.0%** текстов запросов benchmark дословно встречаются в train, после нормализации 37.5%.

**Что это значит для решения.** Валидацию строить по уникальным запросам и с групповым сплитом по `search_query`, иначе оценка будет завышена популярными короткими запросами. Около 10% запросов с опечатками — аргумент за char n-gram (TF-IDF по char 3–5) или fuzzy-канал. Для 37% «знакомых» запросов сильный канал — история кликов из train.

## 5. Рекомендации

**Поля для лексического индекса:**
1. **title** — главный вес. Короткий и точный, но полностью покрывает только 17–48% запросов.
2. **params** — индексировать не всю строку, а значения без служебных ключей («Место оказания услуг», «Тип стоимости», «Время для связи…», цены и время). Ценное в params — названия услуг («Услуги Замена масла…», «Название услуги…»), «Тип», «Вид», «Специальность», марки авто.
3. **description** — обязательно, с меньшим весом: BM25 с отдельным полем или truncation. Даёт +8.7 п.п. пар с хоть каким-то совпадением и в 2 раза больше полных покрытий запроса.

**Морфология:** нужна. Prefix5 даёт +12–15 п.п. на title. Без pymorphy достаточно Snowball-стеммера (если доступен), усечения до 5–6 символов или char n-gram TF-IDF (3–5). Char n-gram заодно ловит опечатки (около 10% запросов) и композиты.

**Фильтры:**
- **Hard (безопасно)**: «Вид услуги X» и «Тип услуги X» (кроме значения «Другое» — только soft). Теряют 1.6–2.1% целевых, сужают корпус примерно в 15 раз. Лучше как «hard с fallback»: основная часть из 50 — из отфильтрованного пула, 5–10 слотов без фильтра. Порог выбрать на валидации.
- **Soft (буст/фича)**: «Тип услуги автосервиса» (4%), «Вид/Тип = Другое» (19%), «Предмет или специальность», «Чем вы занимаетесь», «Услуга», «Где вы оказываете», «Кто оказывает (пол)», «Аренда авто…» — нарушения 3–18%.
- **Игнорировать или только как слабая фича**: «Онлайн-запись» (42% нарушений); «Кто оказывает: Частный исполнитель / Компания», «Участие в пилоте CPL», «Срочная услуга», «Поиск по слотам», «Сортировка», «Слова в описании» — по params их не проверить. «Рейтинг ≥4» формально безопасен (0.2%), но в benchmark не встречается. Пустые значения «Вид услуги» / «Тип услуги» ограничением не являются.

## Ключевые выводы

1. **Benchmark похож на уникальные запросы train, а не на строки.** 3.2 токена против 2.3, однословных 4% против 19.5%, опечаток около 10%. Валидировать нужно с группировкой по запросу и макро-усреднением. На хвостовых запросах лексика слабее: все токены в title + params есть лишь у 29%.
2. **Нужны все три текстовых поля и морфология.** title > params > description по точности, но description закрывает ещё около 9% запросов и удваивает полное покрытие. Стемминг или char n-grams дают +10–15 п.п. Около 4% пар не имеют лексического пересечения вовсе (синонимы, композиты, опечатки), и для них нужен семантический канал.
3. **«Вид услуги» и «Тип услуги» почти безопасны как hard-фильтр.** Нарушено 1.6% и 2.1% (2.3% вместе), корпус сужается примерно в 15 раз. Исключение — значение «Другое» (19%). Лучше hard с fallback-квотой.
4. **«Онлайн-запись» (42%) и атрибуты продавца, CPL, срочности нельзя применять жёстко.** Последние вообще не проверяются по данным item.
5. **Фильтров в benchmark вдвое меньше, чем в train (37% против 67%), и совсем нет автосервиса и рейтинга.** Для 63% запросов категорию нужно выводить из текста запроса. Не стоит переобучаться на авто-вертикаль, которая занимает около 12% train.
