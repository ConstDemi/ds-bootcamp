# 08 — Гибрид sparse + dense

Код: `experiments/hybrid.py`. Запуск из корня репозитория: `python experiments/hybrid.py` (~1.5 мин, ~3 ГБ, CPU).
Ретриверы не пересчитываются: сливаются готовые топ-300 из `work/cands/{sparse,dense}_{val,bench}_{all,geo}.parquet`
(sparse = BM25 + стемминг, `06_sparse.md`; dense = e5-small на CPU, int8, seq 64, `07_dense.md` — нижняя граница dense).
Пишет `answer_02_hybrid.csv` и `work/cands/hybrid_{val,bench}_geo.parquet` (топ-300: query_id, item_id, score, rank).

## Методы

- **RRF**: score = Σ 1/(k_rrf + rank) по двум источникам, нет в списке — 0. k_rrf ∈ {10, 30, 60}.
- **Взвешенная сумма**: (1 − w)·norm(sparse) + w·norm(dense), w — вес dense ∈ {0.3, 0.5, 0.7}. norm — min-max или z-score
  по списку источника внутри запроса. Если id нет в списке источника, он получает минимум этого списка (для min-max это 0).
- **Interleave** (контроль): sparse₁, dense₁, sparse₂, dense₂, … без повторов.
- **Добор**: после слияния список дополняется режимом all (сначала sparse, потом dense) без повторов. Выход всегда
  ровно 300 уникальных id, ответ — первые 50. Dense всегда отдаёт 300, поэтому «сабутыльник» (у sparse 0 кандидатов) тоже получает 50.

**Как решён geo.** В geo-списке городского запроса сначала идут объявления города, потом добор из всего корпуса
со своим глобальным скором. Поэтому score может расти по rank. Кандидатов делим на два яруса:
«город» (`item_location_id == search_location_id`) и «добор». Нормировка и ранги считаются внутри (запрос, источник, ярус),
а ярус «город» всегда стоит выше. У регионов и «всей России» совпадений локации нет, там весь список — один ярус.
- Для взвешенной суммы ярусы обязательны: без них min-max 0.5 даёт 0.750, с ними 0.776.
- Для RRF ярусы не нужны, и без них RRF чуть лучше. Ранги geo-списков уже идут в порядке «сначала город», а явный ярус
  ставит нерелевантные городские объявления dense выше релевантного добора sparse. У sparse в городе есть только объявления
  с ненулевым BM25, и у 23% городских запросов их меньше 50. У dense в городской пул попадает весь город (косинус есть у всех),
  то есть до 300 объявлений. Без явного яруса получается «мягкое» гео: объявление, которое оба источника нашли в доборе,
  может обойти городское объявление, найденное только одним.

## Выбор

Все разумные гибриды укладываются в 0.770–0.776, разница в пределах шума. Даже interleave отстаёт всего на 0.005.
Выигрыш даёт сама взаимодополняемость источников, а не способ слияния. Поэтому выбран **RRF k=60 без ярусов** (исходные geo-ранги):
- он не зависит от шкалы скоров. Min-max чувствителен к весу (w 0.5 → 0.6 → 0.7: 0.776 → 0.764 → 0.747) и после
  пересчёта dense на GPU распределение косинусов поменяется, так что вес пришлось бы подбирать заново. RRF почти не зависит от k (0.772–0.773);
- в нём нет логики локаций и подбора весов;
- на всех срезах он не хуже RRF с ярусами, а на @300 выше: 0.897 против 0.889. Для реранкера это полезнее.

В режиме all гибрид почти ничего не даёт (0.414 → 0.41–0.43): без гео оба источника тонут в равнозначных объявлениях по всей стране.

## Взаимодополняемость источников (пары «запрос, правильный id», всего 3088, geo)

- В топ-50 хотя бы один источник находит 2521 пару (81.6%), а гибрид@50 — 2396 (77.6%).
  До «оракула над двумя топ-50» остаётся 125 пар, это работа для реранкера.
- Dense добавляет 217 пар, которых sparse не находит в топ-50 (+9% к 2304 у sparse). Sparse добавляет 385 пар сверх dense.
  Источники заметно дополняют друг друга.
- На бенчмарке топ-50 гибрида совпадает с топ-50 sparse на 70%.

## Что ожидать на платформе

На валидации 0.774. Бенчмарк, скорее всего, даст меньше:
- у 9% запросов бенчмарка `search_category = 0`. Это сложные запросы вне услуг, в валидации их нет. Если на них recall около 0.4,
  общий итог ≈ 0.91·0.774 + 0.09·0.4 ≈ **0.74**;
- доля регионов та же (17%), а перекоса по истории у контентного гибрида нет, так что эта часть переносится честно.

Реалистичный диапазон — 0.72–0.76. Прирост над sparse-only на платформе должен остаться около +0.03.

## Что дальше

1. **Регионы** (18% запросов, 0.49). Сужать регион до его городов по парам search_location → item_location из train[mask]
   и использовать это как пул или буст. Это самый большой резерв.
2. **GPU-dense**: e5-small fp16 seq 256 (на подкорпусе +0.05 R@50), потом USER-base или e5-base. Гибрид пересобирается тем же
   `python experiments/hybrid.py` без подбора параметров, RRF к шкале нечувствителен.
3. **Фильтры в sparse**: буст по совпадению вида и типа услуги из `search_infm_params_text` с параметрами объявления.
4. **Реранкер над топ-300 гибрида** (потолок 0.897, объединение источников — 0.918). Признаки: ранги и скоры обоих источников,
   город или добор, совпадение фильтров, категория и микрокатегория, рейтинг, число отзывов, цена, популярность объявления
   (с учётом того, что история на валидации переоценена). Можно добавить cross-encoder.
5. Мягкое гео (добор, найденный обоими источниками, выше городского мусора) уже дало +0.003. После реранкера это стоит сделать признаком, а не правилом.

## Гибрид с GPU-dense

Dense заменён на **bge-m3** (GPU, fp16, seq 256, geo 0.764, см. `07_dense.md`). Метод прежний: **RRF k=60 без ярусов**, код и параметры не менялись.
`python experiments/hybrid.py` читает те же пути `work/cands/dense_*.parquet`, в них теперь кандидаты bge-m3. Для проверки добавлен вариант «RRF k=30 без ярусов».
