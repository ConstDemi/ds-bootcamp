# Сводка EDA (26.09)

Подробности и код: `01_queries.md`, `02_corpus_popularity.md`, `03_geography.md`, `04_text_filters.md` и одноимённые `*_eda.py`.

## Семь фактов, которые определяют решение

| # | Факт | Цифра | Следствие |
|---|---|---|---|
| 1 | Запрос = текст + локация + фильтры; обычно один выбор на запрос | 354k групп, у 84% ровно один item | Recall@50 ≈ «попали ли в 50 одним-двумя нужными» |
| 2 | Бенчмарк = длинный хвост: по одному запросу на уникальный текст | 63% текстов бенчмарка нет в train | главное — сопоставить текст запроса с текстом объявления |
| 3 | Train и корпус почти не пересекаются | в корпусе 5.3% item train; 90% корпуса никогда не выбирали | история и популярность не работают (baseline ~0.01); train нужен как обучающие пары «текст запроса ↔ текст объявления» |
| 4 | Локация сильная, но не жёсткая | совпадает в 83% пар (93% для городских запросов); 17% запросов бенчмарка по региону или всей России | мягкий гео-пул: свой город → соседние ≤100 км / пары из train → весь корпус; потолок ~0.97 |
| 5 | Слова запроса есть в тексте объявления | хоть одно слово: title 63%, по префиксу-5 78%, в любом поле 96%; 4% без общих слов | лексический поиск со стеммингом по title + params + description, плюс эмбеддинги для синонимов |
| 6 | Микрокатегория почти определяется текстом | ~85% выборов по тексту в одной микрокатегории | классификатор «запрос → микрокатегория» на всех 497k строк как буст (не фильтр: −15%) |
| 7 | «Вид/Тип услуги X» в фильтрах почти безопасен | жёстко отрезает ~2.3% (кроме «Другое» 19%); фильтры есть у 37% бенчмарка | применять с запасной квотой 5–10 мест без фильтра |

Мелочи: `delivery` почти пуст (игнорировать); `search_category` бесполезна; в `item_infm_params_text` служебный текст (ключи, адрес, график) надо чистить; цена −1/0/1 = заглушки; бенчмарк без авто-вертикали.

## Валидация

Бенчмарк нельзя имитировать случайным split строк (завысит). Схема:
- по одной группе (текст, локация, фильтры) на уникальный текст, тексты отбираются равномерно;
- только группы, чей выбранный item есть в `benchmark_items` (иначе искать не в том корпусе);
- поиск по всему `benchmark_items`; macro Recall@50; отдельно срез «текста нет в остальном train»;
- остальные строки train — обучение (исключить из них отложенные группы).

Оговорка: отложенные item — это те 5% корпуса, что встречались в train; на бенчмарке может быть чуть иначе. Первый сабмит покажет расхождение.
