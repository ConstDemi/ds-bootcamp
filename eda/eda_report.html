Город сильно сужает поиск, но жёсткий фильтр опасен

У запросов по городу точный фильтр «только свой город» срезает 6,8% правильных ответов, а у запросов по региону не работает вовсе. Микрокатегория по тексту запроса

У 85% выборов по одному тексту одна и та же микрокатегория (всего их 752). Это повод обучить классификатор «запрос → микрокатегория» на всех 497 тыс. строк и использовать его как бонус. Жёсткий фильтр по одной микрокатегории, судя по этим 85%, потерял бы порядка 15% (это оценка, а не замер), поэтому только бонус.

Что это значит для решения

Решение как RAG без генерации

Кандидатогенерация — это ретривер из RAG: ответ здесь и есть найденные документы, поэтому шага генерации нет, а качество меряется recall@k. Как в RAG, работа делится на офлайн (индексация и обучение, один раз) и онлайн (ретривал на каждый запрос). Это план, а не готовое решение: каждый узел проверяется на валидации, бесполезные выкинем.

Офлайн: индексация и обучение

Выполняется один раз, до запросов. Документы — объявления корпуса, логи — train. Пунктир — необязательный шаг, если останется время.

Против утечки: карта регионов, классификатор и дообучение эмбеддера учатся только на обучающих логах, без golden set, иначе оценка будет завышена. Для финального ответа по бенчмарку всё переобучается на полном train. Чанкинг не нужен: объявление короткое (медиана описания около 1 000 символов), один документ = заголовок + параметры + начало описания.

Онлайн: ретривал одного запроса

Как в LangGraph: сплошная стрелка — следующий шаг, пунктир — условный переход (выбирается одна ветка), две стрелки из одного узла — параллельные ветки, которые потом сходятся.

Golden set: валидация, которая похожа на бенчмарк

  1. Равномерно отобрать уникальные тексты train, по одному запросу (текст, локация, фильтры) на текст.
  2. Оставить только запросы, у которых выбранное объявление есть в корпусе: искать будем в benchmark_items.
  3. Строки этих запросов убрать из обучения; другие запросы с тем же текстом оставить.
  4. Считать Recall@50 как среднее по запросам, отдельно смотреть срез «текста нет в train».

Оговорка: отложенные объявления берутся из тех 10% корпуса, что встречались в train. На бенчмарке картина может немного отличаться. Первая отправка покажет расхождение.
