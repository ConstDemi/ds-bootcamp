# Avito DS Bootcamp — тестовое задание: кандидатогенерация для поиска услуг

По поисковому запросу (текст, локация, фильтры) нужно вернуть 50 `item_id` из корпуса в 189 212 объявлений об услугах.
Метрика — Recall@50, среднее по запросам.

| | Recall@50 |
|---|---|
| локальная валидация (3000 запросов, построена по устройству бенчмарка) | **0.9156** |
| платформа, лучший сабмит (5) | **0.9041** |

> **Начните с главного отчёта — [`docs/report.html`](docs/report.html).** В нём итог, схема архитектуры, графики, выводы и журнал всех экспериментов.
> GitHub не показывает HTML-страницы, поэтому отчёт нужно открыть в браузере: склонируйте репозиторий (или скачайте ZIP через **Code → Download ZIP**) и откройте `docs/report.html` двойным щелчком. Сервер не нужен, ссылки из отчёта ведут на файлы репозитория.

Полное описание решения, валидации, экспериментов и ограничений — в **[SOLUTION.md](SOLUTION.md)**. Журнал сабмитов — [attempts.md](attempts.md).

## Решение в пяти пунктах

1. **Гибридный поиск.** BM25 (леммы + стемы) и эмбеддинги `BAAI/bge-m3`, слияние RRF.
2. **Поиск с учётом географии.** Кандидаты ищутся в городе запроса, в соседних городах и в городах, куда из него часто ходят по train. Регион раскрывается в свои города. Своему городу и крупным городам региона даётся мягкий бонус.
3. **Дообученный эмбеддер.** bge-m3 + LoRA на всех 219 тыс. парах «запрос → выбранное объявление» из train. Он добавляет ~23 кандидата на запрос и признак для ранжирования.
4. **Градиентный бустинг для ранжирования.** 5 моделей LightGBM lambdarank, 59 признаков: скоры поиска, география, микрокатегория, фильтры, качество объявления. Модели обучены на 21 тыс. запросов из train, а не на валидации.
5. **Защита от утечки.** Всё, что строится по train, для обучающего запроса строится без строк его фолда, включая 5 копий дообученного эмбеддера. Валидация нигде не участвует в обучении.

## Как воспроизвести

Вся инструкция по запуску и обучению — здесь, в одном месте.

### Требования

- Linux, Python 3.12, GPU NVIDIA с 8+ ГБ видеопамяти (проверено на RTX 3070 Laptop 8 ГБ, CUDA 13).
- 16+ ГБ RAM, ~15 ГБ свободного места на диске.
- Интернет при первом запуске: скачиваются веса `BAAI/bge-m3` (~2.3 ГБ). Дальше сеть не нужна.
- Данные задания: `train.parquet`, `benchmark_queries.parquet`, `benchmark_items.parquet`.

Все команды запускаются из корня репозитория.

### 1. Окружение и данные

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt                 # ~1 мин, torch 2.14 + CUDA
mkdir -p data                                   # и положить в data/ три файла задания
python src/validation.py                        # валидация (3000 запросов) и train_mask, ~5 с
```

### 2. Быстрая проверка без обучения (~25 мин)

Схема сабмита 1 не использует обучаемых моделей. На ней удобно убедиться, что окружение и данные в порядке.

```bash
python src/pipeline.py --mode val --scheme meta # Recall@50 = 0.869
```

Первый запуск кодирует корпус базовой bge-m3 (~19 мин на GPU) и строит индекс BM25 (~1.5 мин), дальше они берутся из кэша в `work/`.

### 3. Обучение итоговой схемы

```bash
bash train_all.sh                               # или PY=/путь/к/python bash train_all.sh
```

Скрипт обучает всё только на train, валидация не участвует. Если его прервать, повторный запуск пропустит готовые модели и эмбеддинги корпуса. Шаги:

| шаг | команда | что создаёт | время |
|---|---|---|---|
| валидация | `src/validation.py` | `work/val_*.parquet`, `train_mask.npy` | 5 с |
| обучающая выборка бустинга | `src/ltr_big.py sample` | 21 439 запросов из train, 5 фолдов по тексту | 10 с |
| кандидаты гео-схемы | `src/ltr_big.py retrieve` | кандидаты для всех наборов запросов | 3 мин (+19 мин на корпус bge-m3, если его ещё нет) |
| дообучение bge-m3 | `src/ft_train.py` ×6 | `work/models/bge-m3-lora-all` и 5 копий без своего фолда `-f0…-f4` | 40–43 мин на модель на A100 |
| кодирование корпуса | `src/ft_eval.py encode` ×6 | `work/emb/bge-m3-lora-all*_s256.npy` | 6 мин на A100, 15–19 мин на RTX 3070 |
| кандидаты и признаки | `src/ltr_ft.py retrieve`, `features` | ~320 кандидатов на запрос, 59 признаков | 3 + 17 мин, 8 ГБ RAM |
| проверка утечки | `src/ltr_ft.py leak` | таблица в логе | не замерял, минуты |
| бустеры | `src/ltr_ft.py final` | `work/ltr_ft_all/models/ltr_{0..4}.txt` + `ltr.json` | 12 мин |

Всего: ~5 ч на A100 и ~40 мин CPU. На RTX 3070 дообучение на всех парах я не замерял; по первой версии (64 тыс. пар за 26 мин) ожидается ~1.5 ч на модель, ~11 ч на всю цепочку. Одна модель занимает 5.1 ГБ видеопамяти. Я обучал итоговые модели на трёх арендованных A100, по две модели на карту.

### 4. Итоговое решение

```bash
export HF_HUB_OFFLINE=1
python src/pipeline.py --mode val                      # Recall@50 на валидации и срезы
python src/pipeline.py --mode bench --out answer.csv   # ответ на тест + проверка формата (check_answer.py)
```

Прогон занимает ~2.5 мин на RTX 3070, пик RAM ~11 ГБ, видеопамяти ~1.4 ГБ.

**Чего ожидать.** С моими моделями валидация даёт Recall@50 = 0.9156. После обучения с нуля результат будет близким, но не побитово тем же: дообучение и эмбеддинги в fp16 на GPU недетерминированы. Ожидаемое отличие — в пределах погрешности валидации, около ±0.005.

**Если что-то не так.**
- Если нет какого-то обученного файла, `pipeline.py` остановится и напишет команду, которая его создаёт.
- Без GPU пайплайн работает: запросы кодируются на CPU. Но эмбеддинги корпуса и дообучение без GPU займут много часов.
- Процесс ограничен 2 ГБ видеопамяти, ограничение меняется флагом `--max-vram-gb`.

**Необязательно.** `python src/ltr_big.py features && python src/ltr_big.py final` обучает бустинг без дообученного эмбеддера (сабмит 3, 0.901, 25 мин). `ltr_ft.py` без флагов и `ft_train.py --max-pairs 64000` собирают версию сабмита 4 в `work/ltr_ft/`.

## Структура

| путь | что |
|---|---|
| `train_all.sh` | обучение итоговой схемы с нуля одной командой (см. «Как воспроизвести») |
| `src/pipeline.py` | сквозной пайплайн: запрос → 50 id (`--mode val / bench`, `--scheme ltr / meta`) |
| `src/validation.py` | валидация по устройству бенчмарка, строгий Recall@K, срезы |
| `src/text.py`, `sparse.py`, `sparse_lemma.py`, `dense.py` | документ объявления, BM25 (стемы, леммы + стемы), эмбеддинги |
| `src/geo.py`, `geo_run.py` | гео-карты и правила для города, региона и «всей России» |
| `src/rerank_meta.py`, `rerank_meta_exp.py`, `rerank_quality.py` | классификатор микрокатегорий, бонусы метаданных и качества (схема meta) |
| `src/ft_train.py`, `ft_eval.py` | дообучение эмбеддера (MNRL, LoRA, `--excl-fold`), кодирование корпуса, оценка |
| `src/ltr.py`, `ltr_big.py`, `ltr_ft.py` | признаки, обучающий пул и фолды, градиентный бустинг, итоговая схема |
| `src/baselines.py`, `check_answer.py` | бейзлайн «популярное в городе», запись и проверка `answer.csv` |
| `experiments/` | эксперименты, которые не вошли в итог (реранкер, Qwen3, варианты гео, разбор ошибок); таблица — в `experiments/README.md` |
| `eda/*.md` | отчёты по шагам: `00_summary` (данные), `05_validation`, … `19_ltr_ft` (итоговая схема) |
| `eda/*.html` | визуальные отчёты по EDA и валидации |
| `docs/report.html` | итоговый отчёт по всей работе: схема архитектуры, графики, журнал экспериментов |

Данных задания и обученных моделей в репозитории нет. Внешних API решение не использует: все модели open-source и считаются локально. Модели и лицензии перечислены в `SOLUTION.md`.
